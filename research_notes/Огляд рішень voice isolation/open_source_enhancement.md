## Q1. Which models are truly causal with ≤ ~40 ms algorithmic latency and run in real time on one CPU core / Apple Silicon? (dense comparison)

### Takeaway
The truly streaming, CPU-cheap, actively maintained open options in 2026 are: **FastEnhancer** (ICASSP 2026, MIT, 16/48 kHz, fastest single-thread RTF incl. Apple M1/M5; plus a dependency-free int8 C runtime `faster-enhancer.c`), **DPDFNet** (Ceva, Apache-2.0 code, Dec 2025/2026, DeepFilterNet2 + dual-path RNN, 8/16/48 kHz, `pip install dpdfnet` with a stateful `StreamEnhancer`), **GTCRN / UL-UNAS** (MIT, ~24–48 K params, 16 kHz, 32 ms window, ONNX streaming), and the legacy baselines **RNNoise 0.2** (BSD, 48 kHz, 10 ms frames) and **DeepFilterNet3** (MIT/Apache, 48 kHz, 20 ms window, but effectively unmaintained since 2024). Both GTCRN and DPDFNet already have streaming ("online") denoiser runtimes in **sherpa-onnx** (C/C++/Python/Swift/Go/Rust), which is the most practical self-hosted packaging on both macOS arm64 and Linux. Everything in the "high-quality" tier (ClearerVoice MossFormer2/MossFormerGAN, Resemble Enhance, VoiceFixer, Sidon, NVIDIA NeMo Schrödinger-bridge/flow-matching, URGENT-challenge winners) is offline/non-streaming or GPU-generative and unsuitable for turn-taking/barge-in paths.

### Inferences
- Algorithmic latency (window + lookahead) derived from the verified STFT params: RNNoise ≈ 10–20 ms; DeepFilterNet LADSPA/LL = 20 ms (standard DFN2/3 with 2-frame lookahead is commonly cited as 40 ms in the DFN2 paper [arXiv 2205.05474](https://arxiv.org/pdf/2205.05474) — not re-verified here); DPDFNet ≈ 20 ms; GTCRN and FastEnhancer-16k T/B/S ≈ 32 ms; FastEnhancer-48k ≈ 21 ms window; DTLN ≈ 32 ms (8 ms hop). All of these are within the ≤ 40 ms budget; the 16 kHz models (GTCRN, FastEnhancer-16k, DPDFNet-16k) match the ASR's 16 kHz input directly and avoid a 48k→16k resample.
- For this pipeline the best shortlist is: (1) DPDFNet-16k (dpdfnet2/4) or GTCRN via sherpa-onnx online denoiser (one runtime for Mac dev + Linux prod, C++ core, no PyTorch); (2) FastEnhancer-B/S 16 kHz via ONNXRuntime (best quality-per-CPU in the only paper that times Apple Silicon); (3) RNNoise as a zero-risk baseline (already in Pipecat/OBS/EasyEffects). DeepFilterNet3 is still good but its repo has been dormant since 2024-10.
- Per-core compute is a non-issue for any of the ultra-light models: even FastEnhancer-M (2.9 GMAC/s) runs at RTF ≈ 0.04–0.17 single-thread; hundreds of concurrent streams per server CPU are plausible for GTCRN/FastEnhancer-T/B (RTF ≈ 0.01–0.06), though no multi-stream server benchmark was found.
- CoreML is not needed: all shortlisted models run via ONNX Runtime / sherpa-onnx on macOS arm64; GPU brings no benefit at these sizes (per-frame kernel-launch overhead dominates).

### Gaps
- No verified CoreML exports or CoreML benchmarks for any of these models.
- UL-UNAS params/MACs/latency, ULCNet latency, DPDFNet DNSMOS/PESQ table values, DeepFilterNet3 DNS-challenge DNSMOS numbers and exact default lookahead of the shipped DFN3 checkpoint could not be read (arXiv/HF blocked).

- NeMo SE models' causality not stated in the retrieved text (Schrödinger-bridge/flow-matching samplers are iterative and presumably offline — inference only).

## Q2. Which models remove competing speech (babble / TV / other talkers) vs. only non-speech noise? Evidence?

### Takeaway
None of the enrollment-free open models is designed or evaluated to remove a competing *talker*; general (unconditional) SE is trained to keep all speech, so TV dialogue and nearby people largely pass through (babble at low level may be partially attenuated as "noise"). Removal of other voices in open-source form requires either personalized/target-speaker extraction (covered elsewhere) or offline separation; the only "voice isolation" products integrated in LiveKit/Pipecat (Krisp VIVA, ai-coustics, Picovoice Koala) are proprietary.

### Cited Findings
- Microsoft's personalized-SE paper: unconditional speech enhancement models "have a limitation of not filtering out interfering speakers", whereas personalized SE uses an enrollment cue to remove "both the background noise and interfering speakers in real-time" — [arXiv 2110.09625](https://arxiv.org/pdf/2110.09625).
- Microsoft Teams "voice isolation" (which suppresses background speech) is explicitly a personalized (enrollment-based) mode — [Microsoft Tech Community](https://techcommunity.microsoft.com/blog/microsoftteamsblog/voice-isolation-in-microsoft-teams-enables-personalized-noise-suppression-for-ca/4096077).
- DeepFilterNet-based personalized variant exists as a separate research line (dual-stage PSE on DFN2), implying base DFN2 does not do this — [arXiv 2404.08022](https://arxiv.org/pdf/2404.08022).
- DPDFNet authors observed, for DeepFilterNet2 in "always-on" streaming, "occasional leakage of background noise after extended silence periods", and fine-tuned DPDFNet for always-on use — [DPDFNet paper (search snippet)](https://arxiv.org/pdf/2512.16420).
- RNNoise-based plugin exposes a VAD threshold that silences frames whose voice probability is below the threshold ("if probability of sound being a voice is lower than this threshold – it will be silenced") — gating is on "any voice", not on a target voice — [werman/noise-suppression-for-voice](https://github.com/werman/noise-suppression-for-voice).
- The only voice-isolation plugin shipped in livekit/agents is `livekit-plugins-krisp` (`krisp.voice_isolation()`, `voice_isolation_telephony()`), whose default backend is the closed-source `livekit-plugins-krisp-internal` package authenticating against LiveKit Cloud (alternatively own Krisp license); no open-source neural denoiser plugin exists in the livekit/agents tree (verified by file listing, 2026-09-26) — [livekit/agents krisp plugin](https://github.com/livekit/agents/tree/main/livekit-plugins/livekit-plugins-krisp).
- Pipecat's audio filters in main (2026-09-26): `rnnoise_filter` (local, pyrnnoise), `aic_filter` (ai-coustics SDK), `koala_filter` (Picovoice), `krisp_viva_filter` (Krisp) — only RNNoise is open — [pipecat-ai/pipecat src/pipecat/audio/filters](https://github.com/pipecat-ai/pipecat/tree/main/src/pipecat/audio/filters).
- Separation front-ends can hurt zero-shot ASR: study of Meta SAM-Audio + Whisper on Bengali/English titled "When Audio Separation Hurts Zero-Shot ASR" — [arXiv 2603.04710](https://arxiv.org/pdf/2603.04710).
- ClearerVoice's separation model (MossFormer2_SS_16K) separates 2-speaker mixtures offline (SI-SNRi 15.5–22 dB) but does not choose "which" speaker — [ClearerVoice README](https://github.com/modelscope/ClearerVoice-Studio/blob/main/clearvoice/README.md).

### Inferences
- Treat all enrollment-free models in Q1 as "noise-only" for planning: expect TV speech/music-with-vocals and nearby talkers to survive, particularly at SNR > ~0 dB. DNS-style training data put babble into the noise set, so distant/diffuse babble is partly suppressed, but a clear competing voice is speech-like and preserved by design.
- A "keep dominant speaker" heuristic without enrollment would have to combine a streaming separator (2 outputs) with energy/diarization-based selection (e.g., pick the stream matching Sortformer's current primary speaker) — no ready open implementation was found; this belongs with the target-speaker-extraction work.
- Because backchannels ("mm-hm", "yeah") are short, low-energy speech, enrollment-free SE generally preserves them (it keeps speech); aggressive VAD-gating (RNNoise plugin VAD threshold, DFN post-filter, high `attn_limit`) is the main risk of clipping them.

### Gaps
- No open benchmark was found that measures interfering-talker/TV-speech suppression for RNNoise, DFN3, DPDFNet, GTCRN or FastEnhancer; claims either way are unverified.
- URGENT 2025/2026 data composition regarding interfering speech (whether competing talkers are treated as noise) not verified.

## Q3. What is known about ASR degradation from enhancement, and which models are "ASR-friendly"?

### Takeaway
Strong evidence (2022–2026) that single-channel SE in front of modern, noise-robust ASR (Whisper, Parakeet, other large E2E models) often *raises* WER, mainly because of non-linear processing artifacts and over-suppression rather than residual noise. Mitigations: mild settings (attenuation limit), mixing back a fraction of the original signal ("observation adding"), using SE only for VAD/turn-detection/barge-in while feeding ASR the raw or lightly-processed signal, or SE jointly trained/fine-tuned for the ASR back-end. Only FastEnhancer publishes WER alongside SE metrics among the light models.

### Cited Findings
- Iwamoto et al. (Interspeech 2022): decomposing SE errors into noise vs. artifact components, "the artifact component [is] the main cause of performance degradation"; simply adding a scaled version of the observed (noisy) signal to the enhanced one ("observation adding") improves ASR on simulated and real recordings — [arXiv 2201.06685](https://arxiv.org/abs/2201.06685), [ISCA archive](https://www.isca-archive.org/interspeech_2022/iwamoto22_interspeech.html).
- "When De-noising Hurts" (Dec 2025): MetricGAN+ (VoiceBank) denoising degraded ASR "across all noise conditions and models" — Whisper, NVIDIA Parakeet, Gemini Flash 2.0, Parrotlet — on 500 medical recordings × 9 noise conditions — [arXiv 2512.17562](https://arxiv.org/abs/2512.17562).
- A robust-ASR decoupling study found a baseline SE front-end improved every metric "except Whisper ASR WER", attributing it to front-end/back-end mismatch outweighing noise reduction for a noise-robust ASR — [PMC / Computer Speech & Language 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC13249453/), [ScienceDirect](https://www.sciencedirect.com/science/article/pii/S0885230825000464).
- 2026 diagnosis paper attributes degradation to over-suppression, "where the front end removes weak speech cues needed by the recognizer" — [arXiv 2607.11157](https://arxiv.org/pdf/2607.11157) (search snippet).
- "Too Good to Be True" (Univ. Hamburg, May 2026): modern ASR with large-scale noisy training and internal LMs correlates better with human WER, but their robustness/context use makes ASR-WER "uninformative" as an acoustics-focused SE metric; transducer models gave most reliable transcriptions — [arXiv 2605.12107](https://arxiv.org/abs/2605.12107).
- NVIDIA published "Robust Speech Recognition with Schrödinger Bridge-Based Speech Enhancement" (2025), i.e., the NeMo SB SE line is being studied specifically as an ASR front-end — [arXiv 2505.04237](https://arxiv.org/pdf/2505.04237).
- FastEnhancer reports WER on VoiceBank-DEMAND for all light models: GTCRN 3.6, LiSenNet 3.4–3.7, FSPEN 3.6, BSRNN 3.4, FastEnhancer T 3.6 / B 3.2 / S 3.2 / L 3.1 (noisy-input WER and ASR model not captured in the README excerpt) — [FastEnhancer README](https://github.com/aask1357/fastenhancer).
- DPDFNet adds a loss term to "mitigate over-attenuation" and exposes an attenuation limit (`attn_limit_db`, e.g., 12 dB) in CLI/API; sherpa-onnx added "offline attenuation limit" for DPDFNet — [ceva-ip/DPDFNet](https://github.com/ceva-ip/DPDFNet), [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx).
- Generative/"restoration" approaches can hallucinate or alter content; URGENT organizers found hybrid discriminative+generative systems outperform pure ones on their metric set (which includes downstream metrics) — [emergentmind USE summary](https://www.emergentmind.com/topics/universal-speech-enhancement), [arXiv 2505.23212](https://arxiv.org/abs/2505.23212); ICASSP 2026 URGENT baseline updated a "phoneme similarity calculation" (content-preservation metric) — [urgent2026_challenge commit log](https://github.com/urgent-challenge/urgent2026_challenge).

### Inferences
- For a Nemotron/Parakeet-family streaming ASR (trained on large noisy data), expect little or negative WER benefit from denoising on stationary noise; the likely net win is on turn detection / VAD / barge-in false triggers. A practical design: run SE in a side branch that feeds VAD/turn-detector/barge-in logic, and A/B-test feeding ASR (a) raw, (b) SE output, (c) SE output with attenuation limit 6–12 dB or 10–30% dry mix-back (observation adding).
- "ASR-friendly" candidates among the streaming models are those with a tunable attenuation floor (DPDFNet `attn_limit_db`, DeepFilterNet `--atten-lim`/post-filter off) and discriminative (non-generative) masking; generative models (Resemble Enhance, VoiceFixer, Sidon, SB/flow matching) carry hallucination risk and should not be put in front of ASR for an agent.
- Because enrollment-free SE does not remove competing talkers (Q2), it will not fix the main problem (TV/nearby-people insertion errors) — the WER gains there must come from target-speaker extraction or diarization-based gating.

### Gaps
- No published WER study specifically for NeMo Nemotron streaming ASR (or Parakeet) with RNNoise/DFN3/DPDFNet/GTCRN/FastEnhancer front-ends was found.
- FastEnhancer's WER column's ASR model and noisy baseline were not captured; the ASR-evaluation details of the DPDFNet paper could not be read (arXiv blocked).
